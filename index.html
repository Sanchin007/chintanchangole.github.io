      FUNCTIONAL SPECIFICATION

      Inventory Exception Resolution

      v1.4 · Ready for build
      1 · BUSINESS PROBLEM

      Orders can fail after customer confirmation when marketplace stock, OMS availability and fulfilment-node inventory are not synchronized closely enough.

      2 · USER STORY

      As an operations agent, I need a single exception view with trusted order and inventory context so I can resolve or escalate a blocked order without switching between systems.

      3 · BUSINESS RULES
      • If alternate node has ATP and promise remains valid → propose re-route.
      • If no ATP but replenishment ETA is within tolerance → hold with customer communication.
      • If source data conflicts → route to human review, never auto-cancel.
      • Every decision writes reason code, actor and timestamp to the audit trail.
      4 · ACCEPTANCE CRITERIA
      • Order, SKU, inventory and promise context visible on one screen.
      • Eligible resolution options calculated in under agreed response threshold.
      • Manual override requires reason and is auditable.
      • Successful action synchronizes OMS and channel status.
      • Telemetry captures resolution time, automation rate and reopen rate.
